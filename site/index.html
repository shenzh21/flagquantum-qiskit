bell.py
from qiskit import QuantumCircuit, transpile
from flagquantum_qiskit import FlagQuantumBackend

backend = FlagQuantumBackend()
circuit = QuantumCircuit(2)
circuit.h(0)
circuit.cx(0, 1)
circuit.measure_all()

compiled = transpile(circuit, backend)
result = backend.run(
    compiled, shots=1000, seed_simulator=7
).result()

print(result.get_counts())

它是独立模拟器，还是 Qiskit 适配包？

这是独立可安装的 flagquantum_qiskit 包，提供标准 BackendV2 接口，依赖外部 FlagQuantum 执行量子计算。Qiskit 用来表达与转译线路；结果使用标准 Job / Result。它不注册 AerSimulator(method="flagquantum")，也不是完整 Aer 平替。

支持哪些环境和运行规模？

已验证 Windows、Python 3.11、Qiskit 2.6.2、FlagQuantum 0.3.1 和 Torch 2.14.1+cpu。当前只支持 CPU，可选 single / double 精度；GPU、多算法、分布式和性能调优不在当前范围。默认量子位容量上限20、最多可设24；它是准入限制，不是可运行规模或性能保证。状态、shots 和输出受内存预算约束，预算不是操作系统级峰值配额。

为什么部分功能仍需要 Aer？

Aer 是可选依赖，提供 save 指令、NoiseModel 等对象，也用于独立测试参考。运行时可以转换局部通道表示，但不调用 Aer 模拟器计算线路。基础 Bell、动态控制和通用 V2 包装器不需要 Aer；生产路径没有 Aer 计算回退。

输出会与 Aer 完全相同吗？

不承诺完全相同。随机数序列、Kraus 轨迹分解可能不同；本工具合并连续测量匹配联合读出规则，与 Aer 的逐指令匹配不同；逆序或部分初始化的整体相位仍有 API 差异。理想线路的位序、相位与数值另有严格验收。Bool / Uint 经典表达式和局部噪声转换也有明确范围。

可以继续使用 Sampler / Estimator 吗？

可以使用 Qiskit 通用 BackendSamplerV2 与 BackendEstimatorV2，将 FlagQuantumBackend 传给包装器即可。Estimator 是采样估计，并非默认精确值；需要按包装器及后端能力准备线路。页面中的 Python 示例须在本地环境执行，浏览器不运行量子模拟。
