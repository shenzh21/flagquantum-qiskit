项目汇报2026-11-20flagquantum-qiskit 0.2.0

让 Qiskit 线路
跑在 FlagQuantum 上

我们做了一个 Qiskit 后端插件：用户照常用 Qiskit 写线路、转译、取结果， 但每一个量子数值都由 FlagQuantum 的 CPU 引擎真实计算。中间的适配层负责“翻译”两边不同的约定， 并对不支持的内容明确拒绝，而不是悄悄换用别的模拟器。

01
Q · 我们想要做什么？

把两个世界接起来

用户的线路和工具链都在 Qiskit 里；我们希望这些线路不用改写，就能交给 FlagQuantum 计算，并且结果可信、可复现、可追溯。

Qiskit

用户这一侧

最常用的量子编程框架。用户用 QuantumCircuit 描述线路，用 transpile 把线路改写成后端支持的门， 再通过 backend.run() 拿到 Job / Result；也可以用 Sampler / Estimator 原语。 常用的本地模拟器是 Aer。

FlagQuantum

计算这一侧

flagos-ai 开源的量子模拟框架，基于 PyTorch。它有自己的 fq.Circuit、中间表示 CircuitIR、 状态向量内核、测量与噪声通道。它自带的 Qiskit 导入器只负责把标准门组成的纯量子部分转成 IR。

两边“说的话”不一样 直接对接会出错的地方

方面Qiskit 的约定FlagQuantum 的约定不处理会怎样
振幅位序bit0 是最低位（LSB）wire0 是张量第一个轴（MSB）状态向量、矩阵门、概率全部错位
未写经典位初始为 0完整动态线路默认 -1条件分支判断与 counts 出错
对外接口BackendV2 / Job / Result，counts 用十六进制键Circuit.sample() 返回整数张量无法接入 Qiskit 工具链与原语
经典控制IfElseOp、ForLoopOp、WhileLoopOp、SwitchCaseOp自有 DynamicCircuit 语义动态线路无法执行或语义不一致
噪声Aer NoiseModel：按门名、标签、量子位匹配Kraus 算符批量作用噪声模型无法使用，或悄悄被忽略
保存结果Aer 扩展：save_statevector 等直接读状态张量拿不到中间状态、概率、期望值

三条目标

用户不改习惯

标准写法 transpile(c, backend) → backend.run() → result() 照常可用，Sampler / Estimator 也能直接包装。

计算只来自 FlagQuantum

不允许在背后偷偷调用 Aer、BasicSimulator 或自己写的矩阵乘法；测试会拦截这些入口来证明这一点。

对标 Aer 的基础功能

批次、参数绑定、动态控制、噪声、保存状态等常用功能语义一致；有差异的地方给出可复现证据并写明。

02
Q · 现在做了个什么东西？以什么形式存在？

一个可安装的 Python 包

名字叫 flagquantum_qiskit，对外只暴露一个类 FlagQuantumBackend。它实现了 Qiskit 的 BackendV2 接口， 所以在 Qiskit 看来，它就是和 Aer 同类的一个“后端”。

它是：一个 Qiskit 后端；一层薄的“翻译 + 调度”代码（13 个源文件，约 1900 行，含大量中文注释）； 可从源码构建 py3-none-any wheel 安装包。

它不是：一个新写的量子模拟器（不做矩阵演化）；不是 Aer 的一个方法（不注册 AerSimulator(method="flagquantum")）； 不是云服务或异步队列（Job 同步完成）。

依赖锁定：Python 3.10–3.12（实测 3.11）、qiskit==2.6.2、flagquantum==0.3.1、torch==2.14.1（CPU）。 可选 qiskit-aer==0.18.4，只用于提供保存指令和 NoiseModel 对象，不用来计算。

Q · 如何使用？

和用 Aer 的写法一样

在仓库根目录从源码安装，导入 FlagQuantumBackend，其余都是标准 Qiskit 写法。下面每段代码右侧的输出，都是原汇报准备时真实运行得到的历史快照；本次迁入未重新计算。

安装 Windows · PowerShell

  1. 在仓库根目录建立隔离环境（已有环境可跳过）
    py -3.11 -m venv .venv
  2. 安装 CPU 版 Torch
    .venv\Scripts\python.exe -m pip install torch==2.14.1+cpu --index-url https://download.pytorch.org/whl/cpu
  3. 安装本工具（会带上 Qiskit 2.6.2 与 FlagQuantum 0.3.1）
    .venv\Scripts\python.exe -m pip install .
  4. 需要噪声模型或保存指令时，再装可选依赖
    .venv\Scripts\python.exe -m pip install qiskit-aer==0.18.4
  5. 运行示例
    .venv\Scripts\python.exe examples\bell.py

05
Q · 这个东西是如何实现的？

三方分工，适配器只做“翻译与调度”

核心思路：Qiskit 管“描述与转译”，FlagQuantum 管“量子数值”，适配器夹在中间，只做格式转换、经典逻辑和结果整理，自己不碰量子态的演化。

Qiskit描述与转译
  • 用户构建 QuantumCircuit
  • transpile 读取后端的 Target，把不支持的门分解成 17 种原生门
  • 提供 Result、Job 接口和结果格式化
  • 提供 Sampler / Estimator V2 通用包装器
不负责：任何数值计算
适配器翻译与调度
  • 校验选项、线路、参数、资源预算
  • 选择执行路径（快路径 / 通用路径）
  • 把线路转成 FQ 指令，保留用户附带信息（sidecar）
  • 解释 if / for / while / switch、经典位读写
  • 把 NoiseModel 转成 Kraus 算符和读出矩阵
  • 位序转换、结果映射、保存聚合
不负责：矩阵乘态、测量坍缩、通道演化
FlagQuantum量子数值
  • 创建初态、执行门
  • 测量坍缩、reset
  • 按 Kraus 算符抽取噪声分支
  • 整体采样 Circuit.sample
  • 期望值 expectation_ps
不负责：Qiskit 的经典语义和结果格式

关键决定：按线路特征分两条路走

快路径（True）

满足全部条件时，把整条线路一次性交给 FQ：

  • 只有 17 种标准门 + barrier
  • 测量全部在末尾
  • 没有噪声模型、没有经典条件

执行：Circuit.from_ir(ir).sample(shots)，一次得到全部样本。速度快。

is_fast
(circuit)?
通用路径（False）

只要出现以下任意一项：

  • 中途测量、reset、if / for / while / switch
  • 噪声模型、Kraus 通道
  • initialize、矩阵门、set_statevector
  • save_statevector / probabilities / expval

执行：先编译成 Program，再逐 shot 解释；每个量子操作仍调用 FQ 内核。

六条设计原则 摘自 AGENTS.md / ARCHITECTURE.md

1唯一计算引擎

禁止回退到 Aer、BasicSimulator、Qiskit Statevector 演化或自写 NumPy 演化器；Statevector 只用来“装”FQ 算出的结果。

2版本锁定，私有接口集中

用到的 FQ 内部函数只出现在 fq_ops.py，导入时检查版本必须是 0.3.1，升级要另写设计记录并重新验证。

3位序只在边界转换一次

LSB 与 MSB 的转换集中在 fq_ops / noise，不交换 CX 的控制与目标，不重复应用 layout。

4不支持就明确拒绝

未知自定义门、未支持的表达式和选项，都在执行前报错，而不是丢掉语义继续算。

5用户信息不丢

名称、metadata、寄存器、相位、layout、标签存入 sidecar，结果里原样带回，但不塞给 FQ。

6随机性可复现、不串扰

每个实验用局部随机数生成器，不改全局 RNG；批次第 i 个实验用种子 seed+i。

09
Q · 中间是如何变动的？

量子态与经典位的变化

两个视角：快路径中每个门之后 FQ 状态向量怎样变化；通用路径中每个 shot 如何边测量、边分支、边改写经典位。

视角一：状态向量逐门变化 上一章的例子 · 振幅用指针表示：长度 = 模，方向 = 相位

看点：最后一个 S 门之后，测量概率（指针长度）完全没变，但 |11⟩ 的相位转了 90°（0.7071 → 0.7071i）。 这类“只改相位”的错误，只看 counts 是发现不了的，所以测试里专门逐振幅比较相位。原始的 CY 门本来就会让 |11⟩ 带上 i，转译后的三门组合与它完全等价。
逐门状态：用同一组 FQ IR 指令依次调用 fq_ops.gate 观察得到；正式执行时 FQ 一次性完成这些步骤再采样。

视角二：动态线路逐 shot 执行 通用路径 · 中途测量 + 条件分支

线路：RY(2π/3) 作用在 q0，测量 q0 写入 c0；如果 c0 = 1，就对 q1 执行 X；最后测量 q1 写入 c1。 理论上 q0 有 75% 概率测得 1，于是结果应当约 75% 为 11、25% 为 00。

    Q · 我们实现了什么功能？
    已接通的功能
    
    
    对照 Qiskit 2.6.2 / Aer 0.18.4 的常用功能。“已实现”指本项目有真实 FQ 阳性测试的接口子集，不代表复刻了 Aer 的所有选项。
    
  
    
  
    
  
    
    
    类别状态已接通的接口与语义边界
    
    
      
    后端 / Job / Result已实现transpile → run → counts；批次；memory；metadata；同步 Job，重复 result() 不重算无取消、无异步队列、无云服务
    
      
    参数绑定已实现assign_parameters；Aer 风格 parameter_binds（按索引配对，含 global_phase）不做笛卡尔积；执行前不能有未绑定参数
    
      
    标准门已实现id h x y z s sdg t tdg rx ry rz p u cx cz swap，measure，reset（17 门 × 单/双精度逐振幅验证）其他门需先 transpile；未知自定义门不能冒名
    
      
    初态与矩阵门已实现initialize（字符串 / 整数 / 复向量，子集先 reset 再制备）；UnitaryGate；全寄存器 set_statevector不支持 set_density_matrix
    
      
    状态保存已实现save_statevector / save_probabilities(_dict) / save_expval；single、average、accum、pershot、conditional不支持密度矩阵、幺正、stabilizer 保存，以及 save_expval_var
    
      
    中途测量与 reset已实现真 FQ 坍缩；经典位初始 0；同一位多次写入后者覆盖不返回逐步轨迹日志
    
      
    经典控制流已实现if/else、for（含循环变量）、while、switch（含 default）、嵌套 break/continue；Bool/Uint 表达式不支持 Store、独立 Var、Float/Duration；循环有次数预算
    
      
    噪声已实现Aer NoiseModel 全局 / 局部误差；Pauli、depolarizing、振幅 / 相位阻尼、reset 类通道；Kraus 指令；读出误差局部通道最多 5 位；nonlocal 噪声、自定义 pass、重叠的关联读出组拒绝
    
      
    V2 原语已实现Qiskit BackendSamplerV2 / BackendEstimatorV2，多 PUB、多寄存器Estimator 是采样估计，不是精确值
    
      
    精度与随机数已实现complex128 / complex64；局部 RNG；固定版本下同种子可复现不承诺与 Aer 的随机序列相同
    
      
    无输出线路已实现没有测量也没有保存时，成功返回空数据，不偷偷补测量此时 get_counts 按 Qiskit 规则报错
    
      
    设备仅 CPUdevice="cpu"无 GPU、多机分布式

    与 Aer 0.18.4 已确认的三处差异 都有复现证据；第 1 处的处理方式待定
    
  
    
    
    两个量子位共用的读出误差
    
      
    2 位联合读出矩阵规定“01 必读成 10”。本工具 13 shots 全部得到 10，与矩阵预期一致；Aer 在两条单独测量指令下返回 01，相当于忽略了这条规则（Qiskit 的 measure 只作用于单个量子位，Aer 找不到可匹配的 2 位测量）。Qiskit 本身没有能运行噪声的参考实现，因此这里没有“标准答案”。
        当前做法是按联合矩阵执行；备选做法是遇到多量子位读出误差直接报错，避免与 Aer 结果不同。（tests/results/aer_correlated_readout_difference.json）
    
    
    倒序全量子位 initialize 的整体相位
    
      
    线路带全局相位 0.3 时，Aer 把这个相位多乘了一次；本工具按“先 reset 再制备”执行，保存的振幅与 Qiskit 自己的 Statevector 逐位一致（2026-11-20 复核，最大误差 1.3e-15）。
        所以偏离 Qiskit 的是 Aer，不是本工具。两者物理上是同一个态（密度矩阵差 1.13e-16）。（aer_initialize_phase_difference.json）
    
    
    线路末尾的 while 循环
    
      
    Aer 0.18.4 编译这类线路时报 “Invalid jump destination”，是 Aer 自身缺陷，与本工具无关。对照测试在循环后加一次测量来绕开；本工具的循环终止与超预算另有测试。
    
  
    

  
    一个值得注意的现象：两条路径的速度差 本次运行观察，不是正式基准
